# netcheck: пробы и карта, версия 2

Спецификация по итогам двух исследований с замерами на реальной сети
(прямой выход — российский домашний провайдер, Москва; контрольный выход —
Швеция). Дата замеров: 2026-08-02.

Адреса первых шагов и номер автономной системы провайдера, с которого делались
замеры, в тексте заменены на адреса из диапазонов для документации
(RFC 5737, RFC 5398): к сути выводов они отношения не имеют, а называть
конкретного абонента незачем. Адреса чужой инфраструктуры — Cloudflare,
Google, точек обмена трафиком — оставлены как есть.

Всё ниже — измерено, а не выведено из общих соображений. Что не проверено —
помечено явно.

---

## 1. Что сломано сейчас

### 1.1 `dns_spoof` съедает YouTube (самый тяжёлый)

`analyze.Diagnose` проверяет подмену DNS раньше DPI, а `SameIPSet` сравнивает
голые IP. У любого CDN системный резолв и DoH отдают разные адреса одной и той
же сети — это GeoDNS, а не подмена. Расхождение наблюдалось у 8 из 20 хостов
(youtube, x, github, google, microsoft, netflix, figma, adobe, signal, tiktok,
chatgpt). YouTube и x.com получают диагноз `dns_spoof` вместо `dpi_sni`.

**Правило:** `dns_spoof` ставится только если системный резолв вернул приватный,
loopback или link-local адрес. Расхождение множеств при живом TLS — пометка
`geodns`, не причина.

### 1.2 DoH уходит через прокси из переменных окружения

`probe/dns.go` использует `http.DefaultClient`, а он берёт `HTTPS_PROXY` из
окружения. На машине с запущенным VPN-клиентом DoH-резолв уходит в чужую страну,
а TCP/TLS/HTTP-пробы идут напрямую. «Честный IP» снимается не оттуда, где мы
меряем — расхождение с системным DNS гарантировано, и оно же кормит баг 1.1.

**Правило:** транспорт DoH — только с `Proxy: nil`. Контрольный резолв через
прокси — отдельная функция.

### 1.3 Берётся только первый IP

`runner.go` берёт `firstOr(DoHIPs, ...)`. У notion.so один из двух адресов мёртв
целиком: `208.103.161.1` — таймаут, `208.103.161.2` — TLS ОК за 385 мс.
DNS отдаёт их в случайном порядке, и вердикт превращается в подбрасывание монеты
(наблюдалось 8/8 успехов, потом 10/10 таймаутов).

**Правило:** перебирать до трёх адресов, прежде чем говорить `ip_block`.

### 1.4 3xx-эвристика ставит диагноз в неположенном месте

`HTTPGet` сам решает, что редирект на чужой домен — заглушка провайдера. 31 хост
из 52 отдаёт 3xx на `GET /`. Ложные `isp_stub`: `dzen.ru` → `sso.passport.yandex.ru`
(жив), `mail.ru` → `login.vk.ru` (жив), `t.me` → `telegram.org` (один сервис),
`twitter.com` → `x.com` (один сервис), `claude.ai` → `anthropic.com/app-unavailable-in-region`
(это геоблок, а не заглушка).

**Правило:** `HTTPGet` диагнозов не ставит. 3xx = «жив». Решение о заглушке
принимает `analyze` — по хосту в Location и его ASN.

### 1.5 403 — не всегда геоблок

`isGeoRefusal` считает геоблоком любой 403. Контрольный замер через шведский
выход разделяет:

| Хост | Прямо (RU) | Через SE | Что это |
|---|---|---|---|
| `figma.com` | 451 + «not available in your location» | 301 | геоблок, эталон |
| `gemini.google.com` | 403 | 200 | геоблок |
| `spotify.com` | 403 | 301 | геоблок |
| `paypal.com` | 403 | 301 | геоблок |
| `chatgpt.com` | 403 | **403** | антибот Cloudflare |
| `stackoverflow.com` | 403 `Cf-Mitigated: challenge` | **403** | антибот Cloudflare |

**Правило:** 451 → геоблок, уверенно. 403 → нужен контрольный замер и проверка
антибот-подписи (`Cf-Mitigated`, `__cf_bm`, `Just a moment` в теле).

### 1.6 User-Agent `netcheck/1.0` сам ломает замер

`mail.ru` с браузерным UA отдаёт 200, с `netcheck/1.0` — 302 на `login.vk.ru`,
то есть netcheck сам порождает ложный `isp_stub`.

### 1.7 Один нейтральный SNI недостаточен

`example.com` не подходит для CloudFront и Google Cloud LB — они отвергают это
имя сами. Но отвергают **быстро**: `soundcloud.com` → TLSALERT за 162 мс,
`linkedin.com` → EOF за 111 мс, при том что настоящий SNI виснет 8 с. Сейчас оба
получают `unknown` вместо `dpi_sni`.

**Правило:** лестница нейтральных SNI. Признак «сервер отвечает» — любой быстрый
(<1000 мс) исход, включая TLS-alert и EOF. Признак вмешательства — таймаут или
RST на границе бюджета.

### 1.8 HEAD непригоден

`vk.com` отдаёт 418 на HEAD и 200 на GET; `netflix.com` — 405 на HEAD.
Проба — `GET /` без следования редиректам.

## 2. Доказательство DPI по SNI

Один TCP-эндпоинт, меняется только имя в ClientHello:

```
### youtube.com 64.233.161.93 (Google) ###
  youtube.com        TIMEOUT   8000 мс
  www.youtube.com    TIMEOUT   8000 мс
  google.com         OK         109 мс   cert=*.google.com
  example.com        OK         103 мс   cert=*.google.com
```

Повторено на всех четырёх адресах youtube. То же у `x.com`, `discord.com`,
`facebook.com`, `viber.com`, `rutracker.org`.

Именно этот контраст надо показывать пользователю как улику: одно и то же
соединение, разница только в имени.

## 3. Порядок проб на один хост

```
0. DNS
   sysIPs = ResolveSystem(host)
   dohIPs = ResolveDoH(host)            [транспорт БЕЗ env-proxy]
   оба пусты                      => EXIT dns_nxdomain
   sysIP приватный/loopback/LL    => EXIT dns_spoof (доказано)

1. ips = dedup(dohIPs ++ sysIPs), до 3 штук

2. TCP:443 по ips[0..2]
   все fail                       => EXIT ip_block

3. TLS realSNI на первом живом IP  [сохранить цепочку сертификатов]
   ok -> шаг 5, иначе -> шаг 4

4. лестница нейтральных SNI на том же ip:port:
   ["example.com", "d1.awsstatic.com", "www.google.com", <apex того же CDN>]
   real ∈ {timeout, reset} и нейтральный ответил <1000 мс => EXIT dpi_sni
   все нейтральные тоже timeout                          => EXIT ip_block_stateful

5. проверка сертификата (не сетевая)
   цепочка не строится до системного корня => EXIT tls_mitm
   имя не совпало, издатель публичный      -> пометка cdn_cert_mismatch

6. HTTP GET / (без follow, браузерный UA)
   timeout                        => http_drop
   451                            => EXIT geo_block (high)
   403/429 + антибот-подпись      => EXIT antibot
   5xx                            => EXIT service_down
   3xx на чужой домен | 403       -> шаг 7
   2xx | 3xx на свой домен        => EXIT ok

7. контрольный замер через прокси (если он есть)
   ответ отличается   => geo_block
   ответ такой же     => antibot | ok
   прокси тоже мёртв  => proxy_fails_too
```

Ранний выход экономит главное: на явном `ip_block` не тратятся четыре лишних
таймаута. Сейчас на один заблокированный хост уходит до 5 × 3 с = 15 с.

## 4. Причины, по приоритету

| # | Причина | Условие | Уверенность |
|---|---|---|---|
| 1 | `dns_spoof` | sysIP приватный/loopback/link-local | high |
| 2 | `ip_block` | TCP:443 fail по всем IP | high |
| 3 | `dpi_sni` | TCP ok ∧ TLS(real) ∈ {timeout, reset} ∧ ∃ нейтральный SNI <1000 мс | high |
| 4 | `tls_mitm` | TLS ok ∧ цепочка не валидна ∧ издатель не из системных корней | high |
| 5 | `geo_block` | HTTP 451 | high |
| 6 | `antibot` | 403/429 ∧ антибот-подпись | high |
| 7 | `geo_block` | контроль ≠ прямой замер | high |
| 8 | `service_down` | 5xx | high |
| 9 | `http_drop` | TLS ok ∧ HTTP timeout ∧ контроль ok | medium |
| 10 | `isp_stub` | 3xx на чужой домен ∧ хост Location в AS провайдера | medium |
| 11 | `antibot` | 403 ∧ контроль == прямой | medium |
| 12 | `proxy_fails_too` | прямо fail ∧ контроль fail | medium |
| 13 | `ip_block_stateful` | TCP ok ∧ все SNI timeout | low |
| 14 | `unknown` | иначе | low |

`Outcome` (`ok|timeout|reset|refused|tlsalert|eof|dnsfail`) вместо нынешнего
`Status{ok,warn,fail}`: класс ошибки сейчас теряется, а именно он различает DPI
и честный отказ сервера.

## 6. Сертификат как улика

`InsecureSkipVerify: true` оставить — иначе не увидим сам факт подмены,
соединение просто оборвётся. Но цепочку надо доставать и проверять вручную:

| Наблюдение | Трактовка |
|---|---|
| цепочка валидна, имя совпало | подмены нет |
| имя не совпало, издатель — публичный CA | косяк CDN, не MITM |
| цепочка не строится до системного корня | доказанная подмена |
| издатель не из системного хранилища + имя не совпало | заглушка/DPI-MITM |

Пример второй строки: `www.msftconnecttest.com` предъявляет `CN=a248.e.akamai.net`
от DigiCert. Имя не совпадает, но это не MITM.

## 7. Карта: почему «страна сервера» — враньё

- Сервер YouTube, который нам отвечает, стоит **в Москве** (Google GGC).
  Discord, x.com, chatgpt, signal, rutracker — за Cloudflare, отвечает
  московский PoP (`/cdn-cgi/trace` → `colo=DME`).
- Бесплатные геобазы расходятся на одном IP: `142.250.150.100` → US/Mountain View
  у ip-api и ipapi.co, FI/Hamina у ipwho.is и ipinfo.io. Разброс 7000 км.
- 9 целей из 21 геобаза размещает физически невозможно: RTT 38 мс до «Торонто»
  при минимуме по скорости света 80 мс.
- `rutracker.org` — не российский: целиком за Cloudflare, origin снаружи
  не определяется.

Зато измеримо, **где рвётся путь**. Трассировки:

```
instagram 31.13.72.174 : 1 192.168.1.1 → 2 198.51.100.1 → 3..15 тишина
telegram  149.154.167.99: … → 7 185.0.13.75 (Piter-IX, Москва)
                            reports: Destination net unreachable
chatgpt   104.18.32.47  : … → 9 95.71.2.226 (Rostelecom)
                            → 10 172.68.8.49 (Cloudflare, Москва) → цель, 37 мс
```

### Выбранный дизайн: луч до точки обрыва

Линия от пользователя к месту, где путь умер — не к «стране сервиса».

| Ситуация | Отрисовка |
|---|---|
| работает, unicast | сплошная зелёная → маркер PoP |
| работает, anycast | сплошная зелёная → ромб «CDN-точка DME/Москва, не origin» |
| DPI / IP-блок | зелёная до последнего отвечающего хопа, дальше пунктир и красный ✕ с подписью «оборвалось у AS12389 Rostelecom, хоп 7» |
| явный ICMP-отказ | красный ✕ на геолокации отказавшего роутера |
| 403/451 | линия доходит до PoP, оранжевый замок «сервер ответил и отказал по стране» |
| подмена DNS | ✕ у себя, у иконки роутера — до сети дело не дошло |

Красится участок маршрута, а не страна назначения. Юрисдикция сервиса — серый
бейдж без географической точки. Anycast-точки всегда ромбом и всегда подписаны.

### Определение anycast

1. RTT < расстояние/100 мс — физически невозможно. Сильнейший признак.
2. Префикс в списке издателя: `cloudflare.com/ips-v4` (230 Б),
   `gstatic.com/ipranges/goog.json` (4.9 КБ),
   `ip-ranges.amazonaws.com/ip-ranges.json` (2.6 МБ, есть поле `region`),
   `api.fastly.com/public-ip-list` (402 Б). У Akamai публичного списка нет.
3. Нет PTR + ASN из списка CDN — вспомогательный.

### Источники геоданных

Решение: офлайн-база в бинарнике (выбор пользователя), плюс `/cdn-cgi/trace`.

| Что | Лицензия | Размер |
|---|---|---|
| DB-IP IP-to-Country Lite MMDB | CC BY 4.0 | 8.3 МБ |
| iptoasn `ip2asn-combined.tsv.gz` | PDDL 1.0 (public domain) | 8.9 МБ |
| `oschwald/maxminddb-golang/v2` | ISC | — |
| таблица IATA→город (из OurAirports, PD) | public domain | ~20 КБ |

Отвергнуто: MaxMind GeoLite2 (редистрибуция требует согласия — несовместимо
с AGPL §7); CAIDA pfx2as (нет права передачи); bgp.tools (нет лицензии);
ip-api.com (только HTTP и запрещена коммерция); ipinfo.io и список Fastly
отдают 403 на российские IP.

## 8. Правки каталога по замерам

- `signal.org` отдаёт 200 напрямую из РФ — сейчас не заблокирован.

## 9. Что проверить невозможно — честно

- Физический адрес origin за CDN. Для того CDN и существует.
- «Страна» anycast-адреса. Её нет по определению.
- Город по IP: бесплатные базы расходятся на тысячи км. Потолок — страна.
- Кто именно режет: ТСПУ прозрачно и не отвечает на ICMP. Видно, до кого дошло,
  а не кто зарезал.
- QUIC/HTTP3 — не проверено, локальный curl собран без HTTP/3.
- Заглушка провайдера и провайдерский CA — на сети замеров не наблюдались ни разу,
  провайдер использует тихий drop. Ветку писать по спецификации, проверять
  на другой сети.
- 5xx не отдал ни один из 52 хостов.
- Замеры сделаны один раз в одной точке. `notion.so` менял поведение внутри
  сессии — таблица это снимок, а не константа.
