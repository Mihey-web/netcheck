# netcheck — дизайн (утверждён 2026-08-01)

Диагностика интернета одной кнопкой для Windows: почему «что-то работает, а что-то нет»,
особенно при включённом/выключенном VPN. Публичный open-source проект (GitHub, MIT).

## Форма

- Десктопное приложение, одно окно ~960×680 (resizable, min 900×620). Не сервис, не страница
  в браузере, без автозапуска: запустил exe → нажал «Проверить» → получил вердикт → закрыл.
- Стек: **Go + Wails v2** (WebView2, встроен в Windows 10/11). Артефакт — один `netcheck.exe`.
- Фронт: vanilla HTML/CSS/JS, вшит в бинарь. Визуал утверждён по мокапу
  `mockups/netcheck-c-report.html` («терминальный отчёт», SE-HUD стиль meshbrain):
  слева колонка 280px — компактная кнопка «Проверить», «Окружение», «История прогонов»;
  справа — вердикт со светофорной цепочкой слоёв + плотная таблица всех тестов без спойлеров.
- Языки: RU + EN, переключатель в шапке, автовыбор по языку системы. Все строки — через
  словарь message-id → {ru, en}; вердикты собираются из локализуемых шаблонов.

## Архитектура (пакеты Go)

| Пакет | Ответственность |
|---|---|
| `probe` | атомарные сетевые тесты: ping, TCP-connect, TLS-handshake (с управляемым SNI), HTTP GET, DNS-запросы (системный / прямой UDP / DoH). Каждый возвращает типизированный `Result{Target, Method, Path, Latency, Status, Detail}` |
| `env` | снимок окружения: адаптеры, шлюз, IP; признаки VPN — системный прокси (реестр WinINET `ProxyEnable/ProxyServer`), env `HTTP(S)_PROXY`, слушающиеся локальные порты из конфига (определяем протокол: SOCKS5 или HTTP CONNECT), туннель-адаптеры (WireGuard/Tailscale/TAP/OpenVPN по имени+типу интерфейса), маршрут по умолчанию через туннель, tailscale exit-node (`tailscale status --json`, если установлен) |
| `runner` | оркестрация прогона: слои, параллельность, таймауты (3 с на тест, ~15 с на прогон), стрим прогресса в UI по мере готовности слоёв |
| `analyze` | разбор причины для упавших блокируемых целей (см. ниже) |
| `verdict` | чистая функция `(EnvSnapshot, []Result) → Verdict` — правила, покрыта табличными юнит-тестами |
| `config` | `config.yaml` рядом с exe (нет прав на запись → `%APPDATA%\netcheck\`); создаётся с дефолтами при первом запуске |
| `history` | `runs.jsonl` в `%APPDATA%\netcheck\` (последние 100 прогонов), отдаёт список в UI |

Wails-биндинги: `RunCheck()` (стрим событий слоёв), `GetHistory()`, `GetConfig()`/`SaveConfig()`, `SetLang()`.

## Слои проверки (порядок = порядок в вердикте)

1. **Шлюз** — ping шлюза (ICMP через `IcmpSendEcho` WinAPI — работает без прав администратора).
2. **DNS** — резолв контрольных доменов тремя путями: системный резолвер, прямой UDP к
   8.8.8.8/1.1.1.1, DoH (cloudflare-dns.com, при недоступности — dns.google: из РФ Cloudflare-DoH
   бывает придушен). Расхождение A-записей → «провайдер подменяет DNS».
3. **Рунет** — ping + HTTPS: `ya.ru`, `vk.com` (из конфига).
4. **Заграница (неблокируемая)** — ping `1.1.1.1` + HTTPS `wikipedia.org`, `cloudflare.com`.
5. **Блокируемые сервисы** — `youtube.com`, `discord.com`, `instagram.com`, `x.com` (из конфига).
   Каждая цель проверяется **двумя путями**: напрямую и через каждый обнаруженный локальный
   прокси (SOCKS5/HTTP). ICMP часто режется — падение ping не считается фейлом слоя,
   решают TCP/TLS/HTTP.

## Разбор причины (`analyze`, для каждой упавшей блокируемой цели)

Порядок проверок, первый сработавший даёт диагноз:
1. **Подмена DNS** — системный A-ответ ≠ DoH-ответ (или указывает на известную заглушку/частный IP).
2. **Блок по IP** — TCP:443 к DoH-адресу не коннектится (timeout/refused), при этом тот же тест через прокси проходит.
3. **DPI по SNI** — TCP:443 коннектится, TLS с настоящим SNI рвётся (reset/timeout), TLS к тому же IP с нейтральным SNI - рукопожатие проходит (`InsecureSkipVerify`, важен факт handshake).
4. **Заглушка провайдера** — HTTP отвечает редиректом/страницей из списка известных заглушек.
5. Иначе — «недоступен, причина не определена».

Если цель упала и через прокси — отдельный диагноз «не работает и через VPN — проблема на стороне VPN».

## Вердикт

1–3 предложения человеческим языком (RU/EN), собираются из фактов: первый сломанный слой,
список заблокированных сервисов с механизмами, работоспособность через VPN, предупреждения
(например «VPN-прокси запущен, но системный прокси выключен — браузер ходит мимо VPN»).
Плюс светофорная цепочка слоёв и полная таблица тестов (слой/цель/метод/путь/время/результат).

## Конфиг (дефолт создаётся сам)

```yaml
lang: auto            # auto|ru|en
targets:
  runet: [ya.ru, vk.com]
  global: [wikipedia.org, cloudflare.com]
  blocked: [youtube.com, discord.com, instagram.com, x.com]
ping: {gateway: true, global_ip: 1.1.1.1}
proxy_ports: [10808, 10809, 2080, 2081, 7890, 7897, 1080]
timeouts: {probe_ms: 3000, run_ms: 20000}
history_keep: 100
```

## Прод-обвязка

- MIT, `README.md` (EN) + `README.ru.md`, скриншот в шапке.
- GitHub Actions: на тег `v*` — сборка `netcheck.exe` (windows/amd64) + релиз; на push — тесты.
- Версия зашита через `-ldflags`.
- Никакой персональщины в коде — только дефолтный конфиг.
- Шрифт: `space_engineers.ttf` — проприетарный ассет игры, в репозиторий и сборку НЕ кладём.
  В приложении — системный Bahnschrift SemiBold Condensed (штатный в Windows 10/11) с fallback
  на Segoe UI: ноль ассетов в репозитории и никаких лицензионных вопросов.

## Тесты

- `verdict` и `analyze` — табличные юнит-тесты (набор сценариев «результаты → диагноз»),
  это ядро ценности продукта.
- `probe`/`env` — юнит-тесты на парсинг (реестр/route/tailscale-json — на фикстурах);
  живые сетевые тесты — за build-тегом `integration`.
- Smoke: `wails build` в CI.
