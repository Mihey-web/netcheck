# netcheck

**Одна кнопка. Говорит, почему не работает интернет — и не VPN ли тому виной.**

🇬🇧 [English version](README.en.md)

`ping` скажет, что хост недоступен. Он не скажет, *почему*. netcheck прогоняет батарею
проверок по слоям и отвечает словами: это ваш Wi-Fi, подмена DNS у провайдера, DPI —
или тот самый VPN, который вы только что включили.

![netcheck](docs/screenshot.png)

## Что именно проверяется

Слой за слоем, снизу вверх — вердикт указывает на первое сломанное звено:

1. **Шлюз** — ICMP до роутера. Не отвечает → пробуем TCP до внешнего адреса: прошёл —
   значит режется просто ICMP, идём дальше; не прошёл — сети нет, и прогон
   останавливается, потому что все остальные слои соврут одинаково.
2. **DNS** — резолв контрольных доменов двумя путями: системный резолвер и
   DNS-over-HTTPS в обход системного прокси.
3. **Рунет** — российские сайты, чтобы отличить «всё лежит» от «VPN сломал
   российский трафик».
4. **Заграница** — обычные зарубежные хосты, которые никто не блокирует.
5. **Блокируемые сервисы** — YouTube, Discord, Instagram, X и ещё полсотни на выбор.
   Каждый проверяется **дважды**: напрямую и через локальный прокси вашего VPN-клиента.
   Так видно разницу между «провайдер режет, VPN спасает» и «не работает даже через VPN».

Для каждой упавшей цели netcheck определяет *механизм* — и определяет его по **классу
отказа**, а не по факту «не получилось». Молчание до конца таймаута означает вмешательство
на пути; быстрый RST, TLS-alert или EOF означают, что ответил сам сервер. Без этого
различия DPI неотличим от честного отказа:

| Диагноз | Как определяется |
|---|---|
| Подмена DNS | резолвер вернул адрес из приватного диапазона — такого в интернете быть не может |
| Блок по IP | TCP:443 не проходит ни к одному из адресов имени |
| DPI по SNI | TCP прошёл, TLS с настоящим именем молчит, а с нейтральным — сервер отвечает за доли секунды |
| Подмена сертификата | цепочка не проверяется системными корнями — на пути MITM |
| Заглушка провайдера | редирект на чужой домен, которого через контрольный выход нет |
| Геоблок сервиса | сервер ответил 451, либо через другую страну ответ другой |
| Защита от роботов | 403/429 с признаками challenge — и он такой же из любой страны |
| Сервис лежит | 5xx от самого сервиса |

Расхождение системного ответа с DoH подменой DNS **не считается**: у любого CDN это
обычный GeoDNS, и раньше именно оно записывало YouTube в «подмену DNS» вместо DPI.

Разделение двух последних строк — практическое. ChatGPT и Cloudflare-сайты отдают 403
и из Москвы, и из Стокгольма: это не блокировка, а антибот, и лечится он браузером, а не
сменой страны. А Netflix и Spotify закрывают доступ **сами** — тут поможет не любой VPN,
а только выход в подходящей стране.

## Карта: куда доходит трафик

Отдельная вкладка рисует маршрут до каждой цели — луч от вас до места, где путь
кончился. Дошли до цели → сплошная зелёная линия. Не дошли → линия обрывается там,
где ответил последний роутер, и в этом месте стоит крестик с именем владельца:
«AS12389 Rostelecom, шаг 2». Страна, в которой путь оборвался, подсвечивается.

Именно маршрут, а не «страна сервиса», — и это принципиально. У сервиса за CDN страны
нет: адрес `104.18.32.47` числится за США, но отвечает за 32 мс, а из Москвы это
физически невозможно — отвечает московская точка присутствия. Такие точки помечаются
ромбом и подписываются отдельно, вместо того чтобы красить США. Зато измеримо, до
какого места дошли пакеты, — оно и отмечено.

Есть третий случай, который легко перепутать с обрывом: сервис отвечает, а трассировка
до него не доходит. Это не блокировка, а фильтрация ICMP по пути — половина магистральных
роутеров не отвечает из принципа. Такой маршрут рисуется приглушённо и подписывается
честно, а не крестиком, который противоречил бы отчёту на соседней вкладке.

Точность бесплатных геобаз — страна, поэтому все шаги внутри одной страны показываются
одной отметкой: рисовать десять точек по России только потому, что там десять роутеров,
значило бы изображать знание, которого нет. База зашита в бинарник (DB-IP Lite, CC BY 4.0)
— карта работает, когда сеть уже сломана, и ни один адрес не уходит наружу.

![Карта маршрутов](docs/map.png)

По желанию (`map.geo_lookup`, по умолчанию выключено) на карту добавляются две метки:
откуда вас видит интернет напрямую и откуда — через VPN. Это единственная функция,
сообщающая наружу ваш IP, поэтому она выключена по умолчанию.

Ещё netcheck читает окружение: активный адаптер и шлюз, слушает ли локальный прокси
(SOCKS5 или HTTP), включён ли системный прокси Windows, держит ли туннель-адаптер
маршрут по умолчанию, использует ли Tailscale exit-node. Отсюда и главная подсказка,
на которой все спотыкаются: *VPN запущен, но системный прокси выключен — браузер ходит
мимо него.*

## Установка

Скачайте `netcheck.exe` из [релизов](../../-/releases) и запустите. Всё — ни установщика,
ни зависимостей, ни прав администратора. Один бинарник ~11 МБ, работает на встроенном в
Windows 10/11 WebView2.

netcheck не ставит службу, не прописывается в автозапуск и не висит в фоне. Открыли,
нажали кнопку, прочитали вердикт, закрыли.

## Настройка

При первом запуске создаётся `%APPDATA%\netcheck\config.yaml`:

```yaml
lang: auto            # auto|ru|en
ui:
  scale: m            # размер интерфейса: s|m|l|xl
  font_hud: ""        # шрифт заголовков; пусто = Bahnschrift
  font_mono: ""       # шрифт данных; пусто = Cascadia Mono
  font_file: ""       # путь к .ttf/.otf, чтобы взять шрифт, не устанавливая его
  tab: report         # вкладка, на которой открыть: report|services|map
services:
  enabled: [ya, vk, gosuslugi, cloudflare, wikipedia, github,
            youtube, discord, instagram, x, chatgpt, netflix, spotify]
  custom:             # свои цели, которых нет в справочнике
    - host: example.internal
      group: runet    # runet|global|blocked|geo
ping:
  gateway: true
  global_ip: 1.1.1.1
proxy_ports: [10808, 10809, 2080, 2081, 7890, 7897, 1080]
map:
  enabled: true
  style: globe        # globe|countries|dots
  spin: true
  geo_lookup: false
timeouts:
  probe_ms: 3000
  run_ms: 20000
history_keep: 100
```

![Вкладка «Сервисы»](docs/services.png)

Руками это править не обязательно: вкладка **«Сервисы»** показывает весь справочник
(полсотни сервисов, разложенных по группам), даёт включить нужные галочками, добавить
свой адрес и применить готовый набор — `quick`, `standard`, `blocked` или `full`.
Хранится выбор идентификаторами, а не адресами: адреса сервисов между релизами меняются,
идентификаторы — нет. Старый конфиг со списками хостов переносится автоматически, ничего
из выбранного не теряется.

Порт, на котором слушает ваш VPN-клиент, добавьте в `proxy_ports`, если его нет в списке.
История прогонов лежит рядом, в `runs.jsonl`.

Шрифт настраивается прямо в приложении (шестерёнка в шапке): можно выбрать любое
установленное в системе семейство либо указать в `font_file` путь к `.ttf`/`.otf` —
файл подставляется в страницу на лету, так что свой шрифт не нужно ни ставить в
систему, ни класть в сборку.

## Приватность

netcheck обращается только к хостам из вашего конфига — тем, которые вы видите и можете
поменять. Никакой телеметрии, никаких открытых портов, ничего не пишется за пределами
`%APPDATA%\netcheck\`.

## Сборка из исходников

Нужны [Go](https://go.dev/dl/) 1.25+ и CLI [Wails](https://wails.io):

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@v2.13.0
wails build
```

Тесты — `go test ./...`. Движки диагноза и вердикта — чистые функции с табличными
тестами: именно там живёт вся ценность продукта. Отдельно есть живой тест, который
ходит в настоящую сеть и потому по умолчанию выключен:

```bash
go test -tags live -run TestLive -v .
```

Методология проверок — что именно измерялось, на каких целях и почему выводы такие —
записана в [docs/superpowers/specs/2026-08-02-probe-v2.md](docs/superpowers/specs/2026-08-02-probe-v2.md).
